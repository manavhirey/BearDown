Do NOT split a small/capped weekly running budget across 3 token runs — the athlete pushed back that a "long run" labeled at 1.1 mi is meaningless when they'd run 2.2 mi in a single session two weeks running.

**Why:** The §4.3.7 +10% weekly cap is an anti-*spike* rule, not a mandate to fragment. When applied literally to a ~2.2 mi/week base and split across the default 3 runs, it produced three ~0.5-1.1 mi runs, and the "long run" was shorter than a distance the athlete had already proven twice. The label stopped matching reality and the athlete called it out.

**How to apply:** Anchor the long run to the athlete's actual logged single-run capacity (from the digest), not to weekly-budget ÷ 3. If the 10% weekly cap conflicts with a meaningful long run, prefer FEWER, more purposeful runs (or hold the long run flat at proven distance = 0% spike) over many tiny ones. Repeating a demonstrated distance is not a spike even if adding a second run pushes nominal weekly volume >+10% — say so explicitly in the flags. Labels must be honest: a "long run" should actually be the week's longest and non-trivial. See [[user-running-progression]].
